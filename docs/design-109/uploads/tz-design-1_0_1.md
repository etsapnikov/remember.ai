# Запомин.ai · ТЗ дизайнеру на 1.0.1

| | |
|---|---|
| **Версия** | 1.0 |
| **Дата** | 16 августа 2026 |
| **База** | Дизайн-система 1.0 (`design-tokens.json`), состояние 1.0, объём `scope-1_0_1.md` |
| **Коды** | **Д-1 … Д-6** |

Контекст в двух строках: продукт — одна петля «наговорил комком → „Запомнил." →
вернулось в нужное время». В 1.0.1 над петлёй появляется первый слой корпуса:
разделы, словарь автозамен, дописывание голосом, markdown, доспрос о людях.

**Неизменные правила системы** (из 1.0, действуют на всё новое): красный только
у жеста записи; зелёный только у «сделано»; синего нет; акцентный цвет — всё,
что продукт сделал сам; галочек и чекбоксов нет; строки буквальные, кнопки в
1–2 слова; минимальный кегль 16; Spectral — реплики продукта, Golos Text —
контент, JetBrains Mono — служебное.

**Главный риск версии для дизайна:** структура не должна превратить продукт в
менеджер заметок. Проверка каждого макета: требует ли элемент от человека
организационного решения? Если да — переделать. Разделы ведёт машина; человек
только поправляет.

## Д-1 · Экран «Разделы» и топик заметки

**Что появляется.** Третья поверхность рядом с Лентой и Неделей (предложи, как
они соседствуют: табы? свайп? — сейчас навигация двухэкранная, это первое
расширение, решение станет прецедентом).

**Уровень структуры: заметка.** Топик — атрибут всей записи (владелец диктует
с ясным намерением: «это список дел», «это идея»), пункты наследуют. В UI нет
ни одного места, где топик правится у отдельного пункта.

**Список разделов:** имя + число заметок (и живых пунктов мелким служебным).
Пустые разделы не показываются; строка «Без раздела» внизу — только если такие
заметки есть. Ни создания раздела впрок, ни перетаскивания, ни иерархии —
раздел рождается из речи или из пикера. Сиды «Дела» и «Идеи» выглядят как все.

**Экран раздела:** заметки списком — первые слова, сводка пунктов по
состояниям, дата; тап — карточка. Визуальный язык ленты, не новый.

**Чип топика на карточке заметки:** тихий, у шапки. Источник различим: назначен
машиной — акцентный цвет («продукт сделал сам»), рукой — нейтральный. Тап →
пикер: существующие разделы + строка «новый…». Правка без празднования —
утилитарное действие; после ручной правки чип больше не меняется машиной
(зафиксировать это в состояниях: «заморожен» никак специально не показываем,
просто нейтральный цвет).

**Тон:** раздел — выборка, не папка. В текстах избегаем «переместить»,
«положить», «папка»; говорим «отнести к…», «раздел», «без раздела».

*Сдать:* навигация с третьей поверхностью (2 варианта), список разделов, экран
раздела, чип+пикер на карточке (машинное и ручное состояния), пустое состояние
единственного вида — «пока пусто: разделы появляются сами из записей».

## Д-2 · Словарь автозамен

**Вход в создание правила:** долгий тап по слову в «Что услышал» → слово
выделено, ручки расширения до фразы (до 3 слов) → шторка снизу:
исходник крупно → инпут замены → предпросмотр строки транскрипта с уже
применённой заменой → кнопка «заменять всегда». Никаких «применить один раз» —
это словарь, не редактор (разовая правка уже есть через «Поправить»).

**Управление словарём:** раздел в настройках: список правил «X → Y», счётчик
срабатываний мелким моно, свайп-удаление с отменой (как в ленте).

**Конфликт жестов:** долгий тап сейчас ничего не делает в «Что услышал»?
Проверить и зафиксировать; если конфликтует с системным выделением текста —
предложи развод (например, долгий тап = наше, выделение = через режим правки).

*Сдать:* флоу от долгого тапа до сохранённого правила (все состояния, включая
клавиатуру), раздел настроек, поведение при фразе из 3 слов.

## Д-3 · Дописать голосом

**Вход:** действие «Дописать» на карточке записи (место — предложи: рядом с
«Поправить»?).

**Экран записи с контекстом:** тот же экран захвата 1.0 (клавиша, кольцо,
отсчёт), плюс тихая плашка контекста: «дописываю: „{первые слова заметки}…"».
Плашка не должна конкурировать с жестом — человек уже решил дописать, экран
не переспрашивает.

**Карточка многосегментной заметки:** сегменты в «Что услышал» разделены тихой
служебной меткой («дописано 16 авг, 14:20» — JetBrains Mono, как статусы);
у каждого сегмента свой плеер аудио. Пункты остаются единым списком — сегменты
видны только в транскрипте. Обновлённый после дописывания пункт получает
пометку «уточнён» (мягко, без диффа).

*Сдать:* карточка с 2 сегментами, экран записи с плашкой, состояние «дописанное
разбирается» (пункты старые видны, новые доезжают).

## Д-4 · Markdown-представление

Для заметок-идей карточка получает блок «Собрано» — тело в markdown между
«Что услышал» и пунктами (порядок предложи: что главнее для идеи — сырец или
сборка?).

**Типографическая система рендера** — в токены: h2/h3 (Spectral? — реплика
продукта или контент? реши и обоснуй), списки, жирный/курсив, инлайн-код
(JetBrains Mono). Таблиц, картинок, ссылок в рендере нет. Блок визуально
помечен как «продукт сделал сам» (акцент) — это его текст, не транскрипт.

*Сдать:* спека стилей md-подмножества в токенах + карточка идеи с блоком
«Собрано» (короткий и длинный варианты, тёмная тема).

## Д-5 · Доспрос о сущности

**Карточка-вопрос в ленте** (верхняя позиция): «Юля встречается уже дважды —
кто это?» + две кнопки: «рассказать» и «не надо». Акцентный цвет: вопрос —
инициатива продукта. Карточка одна, очереди вопросов не бывает.

**Ответ:** «рассказать» → экран захвата с плашкой «про Юлю» (голос) + тихая
альтернатива текстом (инпут на том же экране? предложи, как не раздуть).
После ответа карточка сменяется тихим подтверждением («запомнил про Юлю»)
и исчезает.

**«Не надо»:** исчезает молча и навсегда для этой сущности. Никаких «вы
уверены».

**Вечерняя точка показа:** тот же вопрос строкой внутри вечернего возврата
(не отдельным уведомлением) — предложи вид, при котором вопрос не ворует
внимание у самих возвратов.

*Сдать:* карточка вопроса (лента), экран ответа голос/текст, подтверждение,
встройка в вечернее уведомление.

## Д-6 · Правка транскрипта — поведение после фикса бага

Инженеры чинят замирание экрана (Р-14.6). От дизайна — зафиксировать целевое
поведение, чтобы фикс было с чем сверять: подсветка источников на время правки
гаснет (уже в 1.0) — гаснет ли мгновенно или растворяется; поле скроллится
внутри экрана или экран целиком; где живёт курсор при открытии («в конце» или
«куда тапнул»); поведение клавиатуры (поле всегда над ней). Одна страница
спеки, без новых макетов.
