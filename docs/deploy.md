# Обновление приложения на телефоне

Цель: владелец не касается телефона при обновлении. Одна команда на маке —
собралось, встало, запустилось.

```bash
scripts/deploy.sh
```

Режимы: `--no-build` (поставить уже собранное), `--watch` (ставить на каждое
изменение исходников), `--find` (только найти телефон и пришпилить порт).

## Что нужно один раз включить на телефоне

Это единственная ручная часть, и обойти её нельзя — `settings` этого ключа не
содержит, а прошивка требует подтверждения с отпечатком пальца на каждую
установку.

**«Для разработчиков» → «Monitor apps installed by ADB» → выключить.**

Пункт **серый и не нажимается, пока выключена «Отладка по USB»** — сначала
включите её (телефон спросит подтверждение), потом снимайте Monitor.

Цена: любой, у кого есть кабель и физический доступ к телефону, сможет ставить
приложения и читать логи. Откат — тот же тумблер обратно.

Остальное `deploy.sh` делает сам при каждом запуске (`prepare_device`), потому
что обновление прошивки возвращает эти проверки:

| ключ | значение | зачем |
|---|---|---|
| `verifier_verify_adb_installs` | 0 | не проверять пакеты, пришедшие через adb |
| `package_verifier_enable` | 0 | то же на уровне менеджера пакетов |
| `install_non_market_apps` | 1 | разрешить установку вне магазина |

## Как скрипт находит телефон

Адрес и порт отладки плавают: Wi-Fi-отладка выдаёт случайный порт при каждом
включении, DHCP меняет адрес. Порядок поиска: уже подключён → `.deploy-target`
из прошлого запуска → mDNS → скан подсети. Найдя телефон, скрипт переводит adbd
на постоянный порт 5555 (`adb tcpip`), и следующий запуск попадает сразу.

После перезагрузки телефона порт снова случайный: разбудите телефон, включите
«Отладку по Wi-Fi», запустите скрипт — он найдёт устройство сканом и снова
пришпилит порт.

## Самообновление из приложения — почему не используется

Реализовано полностью (`update/SelfUpdater.kt`), включается `SELF_UPDATE=1`.
Замысел: с Android 12 приложение, обновляющее **само себя**, вправе поставить
APK без единого окна — `PackageInstaller` + `USER_ACTION_NOT_REQUIRED`.

На Honor Magic6 Pro (MagicOS, Android 16) это **не работает**. Проверено начисто,
при всех выполненных условиях:

- установщиком пакета записано само приложение (`adb install -i`) — иначе тихое
  обновление не положено никому;
- `REQUEST_INSTALL_PACKAGES` выдано через `appops`;
- троттлинг снят (`pm set-silent-updates-policy --allow-unlimited-silent-updates`);
- подпись APK совпадает с текущей сборкой (проверяется в `SelfUpdater`);
- владение обновлениями и просили, и не просили — исход один.

Ответ системы: `STATUS_PENDING_USER_ACTION`. Это политика прошивки, а не ошибка
реализации; на другом устройстве ветка должна заработать без правок.

Два замечания на будущее, если ветку будут оживлять:

1. Приёмник не срабатывает, пока процесс приложения не жив — прошивка не
   поднимает его ради бродкаста даже с `FLAG_INCLUDE_STOPPED_PACKAGES`. Скрипт
   поэтому будит приложение перед командой.
2. Обычный `adb install` **без** `-i` записывает установщиком `null` и тем самым
   ломает возможность тихого самообновления. В скрипте `-i` стоит везде.

## Почему цикл долгий

APK весит 393 МБ: внутри веса GigaAM. Сборка ~1 минута, установка ~1 минута.
Если итерации станут частыми — вынести веса из APK в каталог приложения и
доставлять их отдельно, разово; тогда APK ужмётся до десятков мегабайт.
