## Часть А · Гигиена петли (первый приоритет)

### Р-15.1 · Баг: «Дописать» не открывает экран записи
*Приёмка:* «Дописать» открывает захват с плашкой контекста из любого состояния
карточки; во время активного разбора — либо дописывание встаёт в очередь и
переразбор происходит один раз по完 обоих текстов, либо кнопка задизейблена со
строкой «разбираю — дописать можно через минуту» (решение при фиксе; молча
не игнорировать). Регресс-тест в смоуке.

### Р-15.2 · Анимация разбора на карточке
Между квитанцией и пунктами карточка никогда не показывает статичную пустоту:
статусная строка «разбираю…» с живым индикатором (характер — Д-9) + скелетоны
на местах будущих пунктов; по доезду пункты замещают скелетоны без прыжка
раскладки. Тайм-аут/ошибка → строка «не смог разобрать — повторить» (словарь
строк 4.1 PRD).
*Приёмка:* с включённым троттлингом сети (10 с ответа) карточка живая всю
паузу; раскладка после доезда не сдвигается более чем на высоту статусной
строки; ошибка кликабельна и перезапускает разбор.

### Р-15.3 · Раздел виден на заметке
Чип раздела в шапке карточки (машина — акцент, рука — нейтраль; спроектирован
в Д-1 1.0.1, не доехал — доводим) + тихое имя раздела в строке заметки в ленте.
Закрывает открытый вопрос Д-1№2: показываем и в ленте.
*Приёмка:* заметка с топиком показывает чип в карточке и подпись в ленте;
«Без раздела» в ленте не подписывается (тишина вместо шума); тап по чипу —
пикер (существующее поведение).

### Р-15.4 · Тап по пункту: раскрытие вместо правки
Тап — read-only раскрытие: полный текст, окно/статус/дата, подсветка
`raw_span` в транскрипте, история жизни (создан → возвраты → переносы →
развёртки). Правка — за явным жестом из раскрытия (жест — Д-8): единый лист
«текст + окно + **дата**» (дата-пикер — см. Р-15.7); тип пункта — за отдельным
«ещё» на листе (правится редко, машина обычно права; метрика
`edit_item(field=type)` — сторож возврата ближе).
*Приёмка:* из раскрытия ничего нельзя изменить без второго жеста; правка окна
≤ 2 жестов от карточки, типа ≥ 3; «сделал/позже/не надо» из уведомлений не
тронуты; случайный тап не мутирует ничего.

### Р-15.5 · Выпил настройки разбиения записи
Глобальный тумблер удаляется. Решение — за харнесом, консервативно: **по
умолчанию не бить**; бить только при двух явно несвязанных и обе содержательных
темах (хвост «и молока купить» к идее — остаётся пунктом, не заметкой).
Разбиение видно: в карточке строка «разделил на две — вот вторая» (ссылка),
действие «склеить обратно» одним тапом (объединяет заметки и переразбирает).
*Приёмка:* фикстура «идея + бытовой хвост» не бьётся; фикстура «две развёрнутые
несвязанные темы» бьётся, обе заметки ссылаются друг на друга; склейка
восстанавливает одну заметку без потери пунктов и их состояний; настройки не
содержат пункта разбиения, миграция снимает старое значение.

### Р-15.6 · Полиш-проход
Совместный аудит шести поверхностей (список известных точек — Д-7): переходы
трёх поверхностей, вертикальный ритм карточки (правило: пункты главные,
остальное сворачиваемо), пустые состояния, карта хэптики, профилирование
ленты/разделов на 1000+ заметках.
*Приёмка:* чек-лист Д-7 закрыт попунктно; скролл 1000 заметок без просадок
ниже 60 fps на Honor; у каждого экрана есть пустое состояние.

## Часть Б · Точная дата возврата

### Р-15.7 · `due_kind: exact` из речи и рукой
**Из речи:** «вернуть 10 сентября» → exact. Правила вывода в коде: год — всегда
ближайший будущий; время без уточнения — утреннее окно этого дня; прошедшая/
неразборчивая дата → пункт без даты с пометкой «не понял дату — поставь».
Фраза уровня заметки («верни мне это десятого») применяется ко всем живым
пунктам; точечная («счёт оплатить десятого») — к своему. Планировщик физически
не ставит возврат в прошлое (ассерт).
**Рукой:** дата-пикер в листе правки (Р-15.4). Дата видна в пункте явно
(«вернусь 10 сен»).
*Приёмка (фикстуры обоих уровней):* «10 сентября» 17.08 → 10.09.2026 утро;
«10 августа» 17.08 → 10.08.2027; «послезавтра в шесть вечера» → корректный
exact; «верни всё это в понедельник» ставит дату всем живым пунктам заметки;
ручная дата переживает переразбор (правило заморозки как у топика).

## Часть В · LLM-слой

### Р-15.8 · Развилка застрявших
Пункт с ≥ 3 `snoozed`-циклами при следующем возврате приходит развилкой:
**уменьшить** (малый первый шаг, выведенный из текста пункта) /
**переформулировать** / **похоронить**. «Уменьшить» заменяет текст пункта
(старый — в историю). Тон — только действия, без диагнозов.
*Приёмка:* третий перенос рождает развилку, второй — нет; шаг для «разобрать
гараж» содержит подмножество исходной задачи; генерик-фразы («начни с малого»,
«сделай первый шаг») ловятся стоп-листом в eval; «похоронить» = обычный
dismissed.

### Р-15.9 · «Неделя» → факты недели
Экран заменяется рассказом: 3–5 конкретных наблюдений («закрылось то, что
висело с июля», «раздел „Продукт" двигался каждый день», «три записи об одном —
возможно, зреет затея») сухим языком; наблюдений нет — экран честно короткий.
**Счётчики петли не удаляются** — переезжают в «Для разработчика» как есть
(инструмент kill-критериев dogfood).
*Приёмка:* стоп-лист похвалы («молодец», «отлично», «супер», эмодзи) на 20
неделях-фикстурах; каждый факт проверяем по данным (даты/счётчики сходятся —
ассерты в ярусе 1 на записанных ответах); пустая неделя не рождает выдуманных
фактов.

### Р-15.10 · Лог решений
`note_kind: decision` (детект «решили/договорились/выбрали») + извлечение
что/с кем/когда. Решения складываются в **системный раздел «Решения»**
(навигация структуры 1.0.1, новых поверхностей нет). Формулировка решения —
пункт без возврата; исходник — как обычно.
*Приёмка:* «созвонились с Димой, решили переносить релиз на октябрь» →
decision с who=Дима и датой; раздел «Решения» показывает хронологию; решение
не плодит do-пунктов, если действие не звучало.

### Р-15.11 · Авто-линковка
Разбор получает кандидатов (заметки того же топика + общие сущности + топ
семпоиска, ≤ 8) и возвращает `links[]`: `ref`, причина
(`continues | answers | disputes`), уверенность. Валидатор: ref существует,
самоссылки и дубли отбрасываются, ≤ 3 линка, low → отбрасывается. В карточке —
блок «Связано» (строка = причина + первые слова + дата, тап → заметка).
Линки двусторонние (у старой заметки появляется обратная строка).
*Приёмка:* фикстура-продолжение линкуется с причиной continues; несвязанная
заметка не получает линков (пустой блок не рисуется); удаление заметки чистит
её линки; линки видны с обеих сторон.

### Р-15.12 · Починка структуры
Еженедельная фоновая проверка (вместе со сводкой недели): (а) раздел ≥ 15
заметок и внутри устойчивый кластер (по линкам/семпоиску) → одно предложение:
«в „Идеях" половина про prinim.ai — выделить раздел?» [да / не надо];
(б) ≥ 5 сирот «Без раздела» похожи → предложить раздел. Максимум одно
предложение в неделю; «не надо» по кластеру — не повторять его месяц.
«Да» — массовое переприсвоение с пометкой источника.
*Приёмка:* синтетический раздел с двумя кластерами рождает предложение;
принятие переносит правильное подмножество (сверка по фикстуре); отказ
подавляет повтор; два предложения в неделю невозможны.

### Р-15.13 · Контекст-пак
Вход тремя путями: голосом («собери контекст по авторизации» — детект команды,
не заметки), кнопкой на экране раздела, за период. Выход — markdown фиксированной
структуры: шапка (тема, N заметок, период) → **Решения** (хронология, из
Р-15.10) → **Факты и вводные** → **Открытые вопросы** (незакрытые пункты темы
с возрастом и переносами) → **Сырьё** (цитаты транскриптов). Дата у каждого
утверждения. Только корпус, слова владельца. Доставка: «копировать» + поделиться
`.md`-файлом.
*Приёмка:* пак по разделу с решениями/фактами/висяком собирает все четыре
секции с верными датами; утверждений вне корпуса нет (ручная сверка чек-листом
на 3 паках + стоп-ассерты в eval); пак по пустой теме честно короткий; голосовая
команда не создаёт заметку-мусор.

### Р-15.14 · Интервьюер («покрутить»)
Режим на карточке идеи: продукт задаёт **один** конкретный вопрос, выведенный
из текста идеи; ответ — голосом тем же жестом (плашка «отвечаю: …»); ответ
становится сегментом заметки (механика Р-14.3 целиком); цикл до «хватит» или
закрытия. Вопросы не повторяются, генерик-вопросы («а что дальше?») — брак.
*Приёмка:* три цикла на фикстурной идее дают три разных конкретных вопроса
(eval со стоп-листом); каждый ответ — сегмент с переразбором по правилам
сверки; выход из режима в любой момент без повисших состояний.

### Р-15.15 · Семпоиск-спайк (топливо, без UI)
Локальные эмбеддинги заметок (класс multilingual-e5-small, ONNX, на устройстве;
замер размер/латентность/качество на 20 парах — отчёт). Потребители: кандидаты
Р-15.11 и кластеры Р-15.12. Неподъёмно на устройстве → фолбэк BM25, эмбеддинги
переносятся в 1.1.
*Приёмка спайка:* отчёт с числами и решение go/фолбэк; при go — пересчёт
эмбеддингов старых заметок фоном с прогрессом в «Для разработчика».

## Часть Г · Р-15.16 · Система автотестирования кор-лупа

Три яруса; с этой версии правило: **новая фича/kind/правка промпта без новых
фикстур не мержится** (definition of done).

**Ярус 1 · CI, детерминированный (каждый мерж).**
- `fixtures/notes/`: транскрипты по типам — список дел, покупки, идея, вопрос,
  факт, решение, монолог-draft, смешанная (для разбиения), с явной датой
  (5 вариантов формулировок), с сущностью, с недосказанностью, идея+бытовой
  хвост — **по 3 на тип**, с эталонами ожиданий (yaml: пункты, типы, топик,
  даты, links, split да/нет).
- `fixtures/llm-replies/`: **записанные ответы DeepSeek** на эти фикстуры.
  Клиент LLM получает режимы record/replay: replay в CI (ноль сети и ноль
  недетерминизма), record — команда обновления фикстур с диффом на ревью.
- Покрытие кодовой обвязки: валидаторы (разбор, линки, патч сверки дописывания),
  планировщик дат (год-вперёд, окна, запрет прошлого), топики и заморозка,
  разбиение/склейка, сборка контекст-пака из фикстурной базы, миграции схемы.
- ASR-регресс (локально, не в CI): 5 эталонных wav из сверки 1.0 →
  посимвольное сравнение; гоняется при обновлении GigaAM/рантайма.

**Ярус 2 · Eval против живого DeepSeek (перед релизом и при правке промпта).**
- Те же фикстуры на живой модели, ассерты-диапазоны: извлечено N±1 пунктов;
  типы/kind верны; «10 сентября» → верная дата; разбиение срабатывает только
  где ожидано; линки не выдуманы (ref из переданных кандидатов).
- Стоп-листы: похвала (Р-15.9), генерик-советы (Р-15.8), генерик-вопросы
  (Р-15.14), утверждения вне корпуса в паке (эвристика: именованные сущности
  ответа ⊆ сущности источников).
- Отчёт: `eval-report.md` — процент прохождения по типам, диффы к прошлому
  прогону, стоимость. Гейт релиза: ≥ 90% и ни одного провала стоп-листов;
  ниже — чинится промпт, а не ослабляется тест.

**Ярус 3 · Смоук на устройстве (перед релизом).**
Живая петля: запись → квитанция → разбор → чип раздела → возврат → действие;
дописывание; правка из раскрытия; экран недели. Чек-лист из 12 шагов, полчаса
руками — пока dogfood, этого достаточно.

*Приёмка Р-15.16:* CI падает на подложенном битом ответе модели (мутационная
проверка); replay-прогон всей матрицы ≤ 2 мин; eval-отчёт генерится одной
командой и стоит < $1; правка системного промпта без обновления фикстур
блокируется чек-листом PR.
