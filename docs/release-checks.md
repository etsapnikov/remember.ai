# Что проверяем перед релизом

Четыре вещи, ради которых продукт существует. Прогон: `scripts/release.sh`.

```bash
scripts/release.sh
```

Отвечает не на вопрос «зелены ли тесты», а на вопрос «работают ли фичи».
Упало — в отчёте стоит имя фичи, а не имя класса: сразу видно, что перестало
работать для человека.

## Три яруса

| ярус | что проверяет | цена | когда |
|---|---|---|---|
| 1 — решения | правильно ли разобрали, посчитали срок, назначили раздел | секунды, офлайн | всегда |
| 2 — доставка | дошло ли до человека: лента, шторка, расписание | секунды, офлайн | всегда |
| 3 — живая модель | не поехало ли качество ответов | минуты, деньги | `--live` |

Ярус 1 работает на **записанной плёнке** ответов модели: в прогоне ответы должны
быть одинаковыми, иначе тест проверяет настроение модели. Плёнка привязана к
версии промпта; сменили промпт — `python3 scripts/record_fixtures.py --force`.

Ярус 2 появился в 1.3 и закрыл дыру, которая стоила дорого: **воркеры,
уведомления и расписание не проверял ни один тест**. Всё, что случалось на
последнем метре — между «мы решили» и «человек увидел», — находил владелец на
себе.

## Фичи и их проверки

### 1. Заметка с возвратом

Наговорил, чтобы не забыть → продукт вернул в нужный момент.

| шаг | проверка |
|---|---|
| речь → пункты в ленте | `CaptureToFeedTest` — «наговорил дело» |
| в модель ушёл распознанный текст | `CaptureToFeedTest` — «а не пустая заметка» |
| срок и окно посчитаны | `ReturnPolicyTest`, `ReturnHorizonTest`, `ExactDateTest` |
| возврат назначен | `CaptureToFeedTest`, `NoteRepositoryTest` |
| **напоминание пришло** | `ReturnDeliveryTest` — «человек видит своими словами» |
| **дважды не придёт** | `ReturnDeliveryTest` — «отмечается показанным» |
| **«сделано» / «позже» / свайп** | `ReturnDeliveryTest` |
| снятое дело молчит | `ReturnDeliveryTest` — «удалённое дело не звонит» |
| повторы | `RepeatTest`, `NoteRepositoryTest` |

### 2. Идея → «Покрутить» → дело с возвратом

Наговорил идею, догрумил вопросами, вышел на действие.

| шаг | проверка |
|---|---|
| правила вопроса: длина, повтор, слоты | `SpinTest` |
| **ответ дописывается в тело** | `PeopleAndSpinTest` |
| **ответ не трогает пункты** | `PeopleAndSpinTest` — человек отвечал, а не менял план |
| **круг замыкается сам** | `PeopleAndSpinTest` — после ответа приходит вопрос |
| промолчал — тело не трогаем | `PeopleAndSpinTest` |
| разговор кончается делом | `NoteRepositoryTest` |
| модель молчит — берём заготовку | `NoteRepositoryTest` |
| пропуск считается | `NoteRepositoryTest`, `InterviewPolicyTest` |

### 3. Заметка со списком

Список дел, продуктов, задач.

| шаг | проверка |
|---|---|
| **список — одна запись, а не россыпь** | `CaptureToFeedTest` |
| **список не звонит** | `CaptureToFeedTest` — три продукта ≠ три напоминания |
| разбор списка на пункты | плёнка `list-groceries` |
| markdown в теле | `MarkdownTest` |

### 4. Категоризация в структуру

| шаг | проверка |
|---|---|
| **запись уходит в раздел** | `CaptureToFeedTest` |
| **раздел не заводится дважды** | `CaptureToFeedTest` |
| **живые разделы уходят в промпт** | `CaptureToFeedTest` — иначе модель плодит синонимы |
| выбор раздела моделью | `TopicAssignTest`, `TopicParseTest` |
| починка структуры | `StructureRepairTest` |
| связи между записями | `LinkCandidatesTest`, `LinkValidatorTest`, `CaptureToFeedTest` |

### 5. Люди с контекстом

| шаг | проверка |
|---|---|
| **рассказ пополняет карточку** | `PeopleAndSpinTest` |
| **рассказ не течёт в ленту** | `PeopleAndSpinTest` — иначе человек получает дело, о котором не просил |
| **рассказать можно много раз** | `PeopleAndSpinTest` — карточка копит, а не заменяет |
| аудио рассказа удаляется | `PeopleAndSpinTest` |
| имена, склейка, переименование | `PersonIdentityTest`, `NoteRepositoryTest` |
| контекст в разбор | `ContextPackTest`, `CaptureToFeedTest` |

### 6. Рефлексия по дню

| шаг | проверка |
|---|---|
| **вопрос назначен на сегодня** | `DayReflectionTest` |
| **переносится только если время прошло** | `DayReflectionTest` — здесь съедался вечер |
| **вопрос пришёл** | `DayReflectionTest` |
| **дважды за вечер не спрашиваем** | `DayReflectionTest` |
| уже рассказал сам — не дёргаем | `DayReflectionTest` |
| строка дня в словах человека | `DayLineTest` |
| итог недели | `WeeklySummaryTest`, `WeeklyFactsTest` |

## Распознавание

`AsrOnPhoneTest` гоняет настоящие веса на arm64 и сверяет с эталоном. Не входит
в обычный прогон: `scripts/release.sh --device`.

**Прогон на телефоне сносит приложение вместе с данными** — так устроен
`connectedAndroidTest`. Перед ним обязательно `scripts/backup.sh`, а лучше
гнать на эмуляторе:

```bash
ANDROID_SERIAL=emulator-5560 ./gradlew :app:connectedDebugAndroidTest
```

## Швы

Три подмены ради проверяемости, все помечены `@VisibleForTesting`:

- `PrinyalApp.useLlm` — разбор с плёнки вместо сети;
- `PrinyalApp.useAsr` — «слух» без 310 МБ весов;
- `AudioDecoder.decoder` — файл в сэмплы без медиастека Android.

Швы стоят там, где иначе непроверяем **главный** путь. Транскрипт нельзя
класть в базу заранее, обойдя распознавание: воркер читает заметку до него, и
тест, обошедший этот порядок, обходит вместе с ним всю породу ошибок, которую
должен ловить. Проверено мутацией — с готовым транскриптом тест не замечает
возвращённой поломки связей.

## Чего этот набор не проверяет

- **Экраны.** Тестов интерфейса нет; сломанная вёрстка карточки не покраснеет.
  Вместо них — скриншоты `scripts/capture-audit.sh` и глаз.
- **Качество ответов модели.** Ярус 1 проверяет наш код на записанных ответах;
  поехавшее качество ловится только ярусом 3 и живым использованием.
- **Само распознавание в бою.** `AsrOnPhoneTest` гоняет один записанный клип.
  Как модель слышит владельца в машине или на улице, не знает никто, кроме него.
