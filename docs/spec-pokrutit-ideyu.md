# Промпт-спека: «Покрутить идею» (запомин.ai)

Версия 1.0 — 24.08.2026. Владелец: Евгений. Модель: DeepSeek `deepseek-v4-flash`.

## 1. Рамка механики

Пользователь диктует заметку → жмёт «Покрутить идею» → получает **один** вопрос → диктует ответ → ответ дописывается в заметку → луп повторяется или прекращается. Когда заметка «докручена», кнопка вместо вопроса отдаёт резюме — это естественный конец лупа.

Каждое нажатие = один вызов DeepSeek, **stateless**: в промпт каждый раз кладётся полная заметка со всеми парами вопрос-ответ, история заданных вопросов и свежий ретрив контекста. Никакого состояния между вызовами, кроме самой заметки. При цене flash (~$0.001 за вызов) это дешевле и надёжнее, чем вести диалоговую сессию.

## 2. Вызов

| | |
|---|---|
| Модель | `deepseek-v4-flash`, режим non-thinking (латентность важнее глубины) |
| Формат | `response_format: {"type": "json_object"}` |
| Параметры | `temperature: 0.6`, `max_tokens: 700` |
| Ретраи | пустой `content` — документированная особенность JSON-режима DeepSeek → до 2 ретраев (как в F-30.5 «Параллелей») |
| Бюджет латентности | полный ответ ≤ 4 с; вопрос показываем только целиком (не стримим) |

### Вход, собираемый харнессом

```json
{
  "note": {
    "raw": "<исходная надиктовка, сырой транскрипт>",
    "exchanges": [
      {"q": "<заданный вопрос>", "a": "<надиктованный ответ>"}
    ]
  },
  "asked_questions": ["<все вопросы этой заметки, включая пропущенные>"],
  "skipped_count": 0,
  "context_facts": [
    {"id": "f1", "text": "<факт о пользователе>", "source": "profile|archive", "date": "2026-10-14"}
  ],
  "now": "2026-08-24T21:40+03:00"
}
```

Правила сборки `context_facts` (харнесс, не модель):

- Ретрив top-8..12 фактов по релевантности к тексту заметки: профиль пользователя + похожие/противоречащие прошлые заметки (эмбеддинг-поиск по архиву).
- Похожая прошлая заметка передаётся как факт вида «DD.MM пользователь диктовал: „<суть одной фразой>“, статус: <докручена/заброшена>».
- Фильтр до модели: не передавать чувствительные категории (здоровье, финансовые суммы из чужих заметок и т.п.) и факты о третьих лицах, если эти лица не упомянуты в самой заметке.
- Пустой список — валидный вход (день 1, ретрив не сработал): механика деградирует до вопросов без контекста, см. §9.

## 3. Системный промпт (текст целиком)

```
Ты — движок функции «Покрутить идею» в приложении-диктофоне. Пользователь
надиктовал заметку голосом и нажал кнопку, чтобы додумать её. Твоя задача —
задать ОДИН вопрос, который сильнее всего продвинет заметку, либо, если она
уже докручена, выдать резюме. Отвечай ТОЛЬКО валидным JSON по схеме из
инструкции, без пояснений вокруг.

Работай по шагам:

ШАГ 1 — ТИП ЗАМЕТКИ. Определи:
- hypothesis: идея продукта/фичи/проекта, предположение, «а что если»
- plan: намерение или дело («надо спланировать…», «хочу организовать…»)
- task: конкретное действие, которое надо не забыть
- reflection: наблюдение, переживание, размышление без явного действия

ШАГ 2 — КАРТА СЛОТОВ. Оцени по всей заметке (включая ответы на прошлые
вопросы) пять слотов. Для каждого: filled / partial / empty + точная цитата
из заметки как доказательство (для filled/partial).
- outcome (исход): как выглядит «хорошо получилось»; для hypothesis — суть
  одной фразой, для plan — картинка успеха
- givens (данность): что зафиксировано — даты, бюджет, участники, ограничения
- fork (развилка): главный несделанный выбор
- risks (помехи): что сорвёт план / какое наблюдение убьёт гипотезу
- step (первый шаг): самое дешёвое действие и когда

ШАГ 3 — СТОП-УСЛОВИЕ. Если выполнено — action="summarize", вопрос не задавай:
- hypothesis: outcome + risks + step заполнены
- plan: outcome + givens + step заполнены
- task: step заполнен (со сроком)
- reflection: автостопа нет, но после 6 обменов предложи резюме
Досрочный стоп: последние два ответа пользователя короче ~5 слов ИЛИ
skipped_count ≥ 2 — пользователь устал, сворачивайся в резюме по тому,
что есть.

ШАГ 4 — РАЗБОР КОНТЕКСТА. Для каждого факта из context_facts определи роль
относительно ЭТОЙ заметки:
- contradiction: факт противоречит заметке или показывает повторяющийся
  паттерн (та же идея диктовалась раньше и заброшена; заявленное расходится
  с тем, что человек реально делал)
- prefill: факт уже отвечает на один из пустых слотов
- anchor: факт тематически связан и может сделать вопрос личным
- none: не относится к заметке — не используй его вообще

ШАГ 5 — ВЫБОР ВОПРОСА, строго по приоритету:
1. Есть contradiction → вопрос про него, вне очереди слотов
   («В мае ты диктовал почти это же и забросил — что изменилось?»)
2. Иначе — вопрос в самый пустой слот в порядке важности для типа:
   hypothesis: outcome → fork → risks → step
   plan: fork → givens → outcome → step
   task: step → givens
   reflection: outcome («что ты хочешь с этим сделать?») → fork
3. Если есть prefill для другого пустого слота — вшей его в вопрос как
   допущение, не трать на него отдельное нажатие:
   «Беру, что едете вдвоём, как обычно, — на все каникулы или на часть?»
   (это по-прежнему ОДИН вопрос)
4. Если есть anchor — используй его в формулировке.

ШАГ 6 — ФОРМУЛИРОВКА. Жёсткие правила:
- Ровно один вопрос. Никаких «и ещё», никаких двух вопросительных знаков.
- Открытый, не да/нет (исключение: конструкция допущение+развилка из шага 5.3).
- Не длиннее ~12 слов, максимум 120 символов. Разговорный русский,
  на «ты», без канцелярита — вопрос будет прочитан/озвучен вслух.
- Якорь: по возможности процитируй 2–5 слов пользователя из заметки
  («ты сказал „подешевле“ — какой потолок?»).
- Не больше ОДНОГО личного факта на вопрос, и только тематически
  связанного с заметкой. Вопрос с двумя фактами из жизни ощущается слежкой.
- Не задавай вопрос, на который заметка уже отвечает.
- Не повторяй и не перефразируй вопросы из asked_questions.
- Не два «почему/зачем» подряд (сверься с последним заданным вопросом) —
  между углублениями вставляй конкретизацию.
- Никогда не давай советов и вариантов ответа — только вопрос.

РЕЗЮМЕ (action="summarize"): одна фраза сути + заполненные слоты своими
словами пользователя + первый шаг. Тон — спокойная фиксация, без похвал
(«Отличная работа!» — запрещено).
```

## 4. JSON-схема ответа

```json
{
  "note_type": "hypothesis | plan | task | reflection",
  "slots": {
    "outcome":  {"state": "filled|partial|empty", "evidence": "<цитата или null>"},
    "givens":   {"state": "...", "evidence": null},
    "fork":     {"state": "...", "evidence": null},
    "risks":    {"state": "...", "evidence": null},
    "step":     {"state": "...", "evidence": null}
  },
  "action": "ask | summarize",
  "question": {
    "text": "<сам вопрос>",
    "slot": "outcome|givens|fork|risks|step|contradiction",
    "context_fact_id": "f3 | null",
    "fact_role": "contradiction | prefill | anchor | none",
    "anchor_quote": "<2–5 слов пользователя или null>"
  },
  "summary": {
    "one_liner": "<суть одной фразой>",
    "next_step": "<первый шаг со сроком>",
    "filled": "<2–4 строки: исход/данность/риски словами пользователя>"
  }
}
```

`question` = null при summarize, `summary` = null при ask.

## 5. Валидация в харнессе (детерминированная, до показа)

Модели не доверяем — как `validatePatch()` в F-30.5. Отклоняем ответ и ретраим, если:

1. невалидный JSON или пустой `content`;
2. `action="ask"`, а `question.text` пуст, длиннее 120 символов, содержит два `?`, или не содержит `?` вовсе;
3. `context_fact_id` указан, но такого id нет во входных `context_facts`;
4. `question.text` на ≥0.85 похож (нормализованный левенштейн/триграммы) на любой из `asked_questions`;
5. `fact_role != "none"`, а `context_fact_id = null` (декларация без факта);
6. `anchor_quote` указан, но не встречается в тексте заметки.

Пункт 3, 5, 6 — ключевые: **обязанность задекларировать использованный факт — то, что заставляет модель реально работать с контекстом**, а не игнорировать его. Заодно это телеметрия: по логу видно, какая доля вопросов контекстная и какие факты стреляют.

После 2 неудачных ретраев — фолбэк-вопрос из статического словаря по самому пустому слоту (по 2–3 заготовки на слот×тип), `fact_role="none"`. Луп не ломается никогда.

## 6. Few-shot примеры (кладутся в системный промпт после правил)

**Пример A — plan с контекстом.** Заметка: «надо спланировать новогодние каникулы». Факты: f1 «в октябре ездил с женой в Стамбул, бюджет вёл таблицей», f2 «работает с жёсткими дедлайнами». Ответ: `note_type=plan`, все слоты empty, action=ask, question: «После Стамбула в октябре — на Новый год снова уехать или дома?», slot=fork, context_fact_id=f1, fact_role=anchor.

**Пример B — hypothesis, середина лупа, prefill.** Заметка про фичу-напоминалку + два обмена, outcome=filled, risks=empty. Факт f4: «похожая заметка от 12.05, заброшена». Ответ: action=ask, question: «В мае ты диктовал похожее и забросил — что изменилось?», slot=contradiction, fact_role=contradiction.

**Пример C — стоп.** plan, outcome+givens+step filled → action=summarize, резюме тремя строками, next_step с датой.

(В спеку примеры даны конспективно; в промпт кладутся полными JSON-ами — три штуки достаточно, flash хорошо держит формат при 1M контексте.)

## 7. Поведение UI вокруг (минимум, влияющий на промпт)

- Ответ пользователя дописывается в заметку **сырым**; модель никогда не переписывает исходный текст.
- «Пропустить вопрос» — один тап; пропуск попадает в `asked_questions` и инкрементирует `skipped_count` (модель по нему сворачивается, харнесс после 3 пропусков подряд может вообще прятать кнопку до следующей заметки).
- Резюме показывается как карточка «Идея докручена» и приклеивается к заметке; кнопка после резюме остаётся — нажатие продолжает луп (стоп-условие уже выполнено, поэтому модель пойдёт в оставшиеся пустые слоты).

## 8. Метрики качества механики

- Длина лупа до резюме (медиана; здорово — 3–5).
- Доля контекстных вопросов (`fact_role != none`); цель ≥ 40% при непустом ретриве.
- Доля пропусков по слотам — какой тип вопросов раздражает.
- Динамика длины ответов внутри лупа: укорачивающиеся ответы = вопросы стали хуже или луп затянут.
- Доля заметок, где пользователь вернулся к лупу на следующий день.

## 9. Деградация

| Ситуация | Поведение |
|---|---|
| `context_facts` пуст | обычные слот-вопросы, `fact_role=none` — механика полноценна, просто безлична |
| JSON не прошёл валидацию после 2 ретраев | фолбэк-вопрос из статического словаря (§5) |
| DeepSeek 429/5xx | 1 повтор через 2 с → «не получилось придумать вопрос, попробуй ещё раз», заметка не тронута |
| 402 (кончился баланс) | отдельный текст со ссылкой на кабинет DeepSeek (как в F-30 «Параллелей») |
| Модель ответила отказом | показать текст отказа, луп не продолжать |

## 10. Что сознательно НЕ в v1

- Тюнинг порядка слотов по истории пользователя (какие вопросы он охотнее отвечает).
- thinking-режим для резюме (можно включить `deepseek-v4-pro` на summarize как опцию «качество»).
- Проактивный догруминг без нажатия кнопки (карточка «вчерашняя заметка + вопрос» в холодном такте) — отдельная спека, эта механика для неё переиспользуется целиком.
