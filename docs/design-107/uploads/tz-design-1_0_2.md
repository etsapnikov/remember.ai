# Запомин.ai · ТЗ дизайнеру на 1.0.2

| | |
|---|---|
| **Версия** | 2.0 (заменяет черновик; состав зафиксирован владельцем 17.08) |
| **База** | Дизайн-система 1.0 + токены 1.0.1, ТЗ разработки `scope-1_0_2.md` |
| **Коды** | **Д-7 … Д-16** |

Правила системы неизменны: красный — только жест записи; зелёный — только
«сделано»; синего нет; акцент — «продукт сделал сам»; галочек нет; строки
буквальные, кнопки 1–2 слова; кегль ≥ 16; Spectral — реплики продукта,
Golos Text — контент, JetBrains Mono — служебное.

Главное новое в версии: у продукта появляется **много блоков, сделанных
продуктом** (ответ недели, «Связано», чистовик решений в паке, вопрос
интервьюера, предложение починки). Первая задача — не рисовать их порознь:
см. Д-16.

## Д-7 · Полиш-аудит шести поверхностей (Р-15.6)

Совместный проход по живому приложению → чек-лист с приоритетами → правки.
Стартовые точки: переходы трёх поверхностей (состояние «где я», жест возврата);
вертикальный ритм карточки — блоков стало много (транскрипт с сегментами,
«Собрано», «Связано», пункты, чип раздела), правило: **пункты главные,
остальное сворачиваемо**; пустые состояния всех экранов единым тоном
(«появится само из записей»); карта хэптики (где вибро есть/не хватает/лишнее).
*Сдать:* чек-лист + правки (макеты — где меняется структура, токены — где
значения).

## Д-8 · Пункт: раскрытие и правка (Р-15.4, Р-15.7)

Тап — раскрытие read-only: полный текст, окно/статус/**дата**, подсветка
источника в транскрипте, история жизни пункта (служебная типографика, 3–5
строк, без таймлайн-графики). Вход в правку — явный жест (предложи 2 варианта:
карандаш в раскрытии / долгий тап как шорткат). Лист правки: текст + окно +
**дата-пикер** на первом уровне; тип — за «ещё» (намеренно далеко). Дата в
пункте видна явно: «вернусь 10 сен».
*Сдать:* раскрытие, лист правки (оба уровня), дата-пикер (и как выглядит
пункт с exact-датой в карточке и в уведомлении), жест входа ×2.

## Д-9 · Анимация разбора (Р-15.2)

Момент между «Запомнил.» и пунктами — главная пауза продукта. Нужен характер
ожидания: статусная строка «разбираю…» с живым индикатором в пластике системы
(не спиннер-заглушка; вспомни кольцо записи — это его родственник) + скелетоны
будущих пунктов + замещение без прыжка. Ошибка: «не смог разобрать — повторить».
*Сдать:* спека движения (кривые/темп/длительности в токены), состояния:
разбираю / доехало / ошибка / долгий разбор (>10 с — меняется ли строка).

## Д-10 · Раздел на заметке + разбиение (Р-15.3, Р-15.5)

Чип раздела в шапке карточки (машина — акцент, рука — нейтраль; из Д-1, довести
до реализации). В ленте — тихое имя раздела в строке заметки (решение по
открытому вопросу Д-1№2: показываем; «Без раздела» — не подписывается).
Разбиение: строка в карточке «разделил на две — вот вторая» (ссылка) +
действие «склеить обратно». Обе — служебные, не празднующие.
*Сдать:* карточка с чипом, строка ленты с разделом, пара разбиение/склейка.

## Д-11 · «Неделя» → рассказ фактов (Р-15.9)

Экран пересобирается: вместо счётчиков — 3–5 наблюдений недели сухим языком.
Композиция: вердикт петли (остаётся) → факты списком без буллет-шума → пусто,
если фактов нет (экран честно короткий, сетка не ломается). Никаких графиков,
процентов, стрелок роста. Счётчики уезжают в «Для разработчика» — там же
спроектировать их размещение (утилитарно, таблицей).
*Сдать:* «Неделя» полная и короткая, «Для разработчика» со счётчиками.

## Д-12 · Развилка застрявших (Р-15.8)

Уведомление третьего переноса: три действия — «уменьшить / переформулировать /
похоронить» (проверить, влезают ли три в системную нотификацию; нет — два +
раскрытие). Экран «уменьшить»: предложенный малый шаг крупно, «заменить» /
«не то». Тон — действия без диагнозов; слово «застряла» в UI не используем.
*Сдать:* нотификация, экран «уменьшить», как выглядит пункт после замены
(старый текст — в истории раскрытия Д-8).

## Д-13 · Связи и починка структуры (Р-15.11, Р-15.12)

Блок «Связано» в карточке: 1–3 строки «причина + первые слова + дата»
(причины: продолжает / отвечает / спорит — подобрать тихие глифы или обойтись
словом), тап → заметка. Блок не рисуется пустым.
Починка структуры: карточка-предложение (в ленте, раз в неделю максимум):
«в „Идеях" половина про prinim.ai — выделить раздел?» [да / не надо] —
родственник карточки доспроса из 1.0.1, тот же жанр «вопрос продукта».
*Сдать:* блок «Связано» (1 и 3 линка, обе стороны связи), карточка починки,
состояние после «да» (что видит человек — тихое подтверждение).

## Д-14 · Контекст-пак (Р-15.13)

Вход: кнопка «Собрать пак» на экране раздела (+ голосовая команда — без UI).
Экран результата: шапка (тема, N заметок, период) → секции (Решения / Факты /
Открытые вопросы / Сырьё) в markdown-типографике Р-14.5 → действия «копировать»
и «поделиться файлом». Это рабочий документ, не праздник: максимально близко
к печатной странице.
*Сдать:* экран пака (длинный контент, скролл), состояние сборки, пустая тема.

## Д-15 · Интервьюер «покрутить» (Р-15.14)

Кнопка «покрутить» на карточке идеи → режим: вопрос продукта крупно (Spectral —
это его реплика) → жест записи для ответа (плашка «отвечаю: …») → следующий
вопрос. Выход — «хватит» всегда на экране. После сессии — заметка с новыми
сегментами (уже спроектировано в Д-3), тихое «добавил к идее».
*Сдать:* экран вопроса, состояние записи ответа, выход/финал.

## Д-16 · Компонент «блок продукта» (сквозной)

«Собрано» (1.0.1), «Связано», ответ недели, вопрос интервьюера, предложение
починки, секции пака — один жанр: **продукт говорит сам**. Спроектировать
единый компонент (акцентная пометка происхождения + заголовок + тело + опц.
действия) и пересобрать все перечисленные на нём. Это удешевит и 1.0.2, и всё
дальнейшее: новые LLM-фичи будут вставать в готовый жанр.
*Сдать:* компонент в токенах + маппинг всех шести случаев на него.
