# Почему разбор шёл минуту

Владелец: «непонятно, почему так долго обработка дипсиком идёт. если из-за
ризонинга — то в первый круг делаем просто флешом без ризонинга…»

Из-за него. Замер: `scripts/eval_reasoning.py`, все тринадцать фикстур, каждая
разобрана дважды — как сейчас и с выключёнными рассуждениями.

| | медиана | суммарно | расходится с ожиданиями |
|---|---|---|---|
| как было | 14,7 с | 343 с | 0 из 13 |
| без рассуждений | **3,4 с** | 47 с | 1 из 13 |

Худшие случаи стоили минуты: `split-two-topics` — 66 с и 8199 токенов
рассуждений, `tasks-mixed-day` — 56 с. Без рассуждений те же записи разбираются
за 5,2 и 3,4 с.

## Что рассуждения покупают

Ровно одно: **деление записи на две темы**. Типы, даты, адресаты, связи,
решения, перечисления — всё сходится одинаково. Единственное расхождение из
тринадцати — `split-two-topics`, где без рассуждений модель оставила две темы
одной заметкой.

Длина не отделяет делимое от неделимого: `idea-course` (319 знаков) и
`idea-with-errand-tail` (154) делить не надо, а `split-two-topics` — 228.
Поэтому порог по длине годится только чтобы отсечь заведомо неделимое.

## Решение (Р-16.1)

Двухфазно, как и предлагал владелец, но вторая фаза узкая:

1. Первый разбор — **без рассуждений**, всегда. Квитанция через ~3 с.
2. Речь длиннее 150 знаков — фоном второй разбор **с рассуждениями**.
3. Второй результат применяется, **только если он поделил запись**. Не поделил
   — выбрасывается: переписывать хороший разбор на равноценный незачем.
4. Человек успел тронуть пункты руками — второй заход отменяется
   (`deep_parse_skipped`).

Пункты при делении пересобираются целиком: половины делят смысл, а не строки.

## Грабли, на которые уже наступили

Первый замер выключал рассуждения через `reasoning: {"max_tokens": 0}`. API
**молча его проигнорировал**: в «выключенном» прогоне модель нарассуждала 49 585
токенов, и сравнение мерило шум — вывод получился ровно обратный правильному.
Тихо игнорируются и `enable_thinking: false`. Работает только
`thinking: {"type": "disabled"}`.

Отсюда правило: замер, выключающий что-то параметром, обязан проверять по ответу,
что оно выключилось. В `eval_reasoning.py` это число токенов рассуждений в обеих
колонках.
