**Резюме.** Android-приложение с одной функцией-петлёй: нажал кнопку в любой момент —
наговорил комок («капли, Соню к лору, мужу про субботу» / «срочно counter клиенту по
цене») — получил мгновенное «Принял.» — через секунды увидел разобранный план — и в
правильные окна того же дня получил возвраты в шторку. Аудио распознаётся **своим**
GigaAM-сервером (звук не уходит третьим лицам), разбор комка делает DeepSeek (уходит
только текст). Ничего из витрины сюрпризов в этой версии нет — версия существует,
чтобы честно ответить на один вопрос: **удерживает ли голая петля**.

**Kill-критерии версии** (из треда, зашиты в аналитику §8):
1. Петля не пережила 2 недели личного использования (W2 жеста < ~30% дней с записью) → продукт закрывается до всякой красоты.
2. Корпус состоит из одиночных команд «напомни в X», а не комков → построен Siri-клон, закрытие.

## 1. Область версии

### В версии (R1)

- Захват: capture-first иконка, виджет 1×1, плитка Quick Settings; оффлайн-очередь.
- Квитанция «Принял.» — мгновенная, до и независимо от распознавания.
- Конвейер: аудио → GigaAM (self-hosted) → DeepSeek-разбор комка → валидация → план возвратов.
- «Доказательство понимания» — карточка плана через ≤ 6 с после стопа.
- Возвраты: локальные уведомления по окнам дня (утро/день/вечер/точное время), «сделано / позже / не надо», авто-перенос проигнорированного.
- Минимальная лента + карточка записи (транскрипт, аудио, айтемы, статусы).
- Локальная аналитика (`analytics.jsonl`) под kill-критерии.

### Вне версии (R2+, не делать даже «быстренько»)

- Доукомплектация, разбор недели, агрегация списков, память фактов, затеи/спарринг — только после выживания петли.
- Гео-окна, семейный контур, iOS, роль системного ассистента (кнопка питания) — R2.
- Live-транскрипт при записи: требует стриминговой ASR; в R1 вместо него пульс+таймер (осознанное отступление от ТЗ UI §3.1, зафиксировать в ТЗ при передаче дизайнеру).
- Онбординг для чужих людей: пользователь один, и это автор.

## 2. Архитектура

```
[Android-приложение (Kotlin)]  — источник истины: SQLite, планировщик возвратов, уведомления
        │  HTTPS + токен, только когда сеть есть
        ▼
[Личный бэкенд (Docker на домашнем сервере/VPS)]
   FastAPI:
     /ingest: audio → GigaAM (ONNX, CPU) → транскрипт
              → DeepSeek API (v4-flash, json_object) → айтемы
              → ответ приложению {transcript, items[], meta}
   Stateless: не хранит ничего, кроме логов по флагу
        │
        ▼
[DeepSeek API]  ← уходит ТОЛЬКО текст транскрипта, не аудио
```

Решения и почему:

1. **Устройство — источник истины.** Все записи, айтемы и расписание возвратов живут в SQLite на телефоне; уведомления — локальные (AlarmManager). Бэкенд падает → петля деградирует, но не теряет данные и не молчит (§6). Никакой push-инфраструктуры.
2. **ASR self-hosted, не в облаке и не на устройстве.** GigaAM (~сотни млн параметров) на телефоне в R1 — лишний риск; на своём CPU-сервере 30–90-секундный клип распознаётся за секунды, аудио не покидает свой контур. Перенос ASR на устройство (ONNX/NNAPI) — исследование R2, вход в архитектуру не меняет (тот же контракт «аудио → транскрипт»).
3. **DeepSeek вызывается с бэкенда,** не с телефона: ключ не хранится в APK, ретраи и логика — в одном месте, транспорт OpenAI-совместимый (наработки из PRD «Параллели» §1.1а переиспользуются: json_object, ретрай пустого `content`, щедрый `max_tokens`).

### 2.1. ASR-стек (GigaAM)

| | |
|---|---|
| Модель | GigaAM-RNNT v2 (open-source, MIT), ONNX-экспорт, инференс onnxruntime CPU |
| Вход | 16 kHz mono PCM; телефон пишет AAC/OGG → бэкенд конвертит ffmpeg |
| Длинные клипы | Silero VAD → сегментация → пофрагментное распознавание → склейка. Для ≤ 90 с обычно 1–3 сегмента |
| Выход | нижний регистр, без пунктуации — это норм: нормализацию, пунктуацию и смысл делает DeepSeek-стадия |
| Числа/имена | известная зона ошибок ASR; правило продукта: айтемы показывают текст **нормализованный моделью**, но транскрипт-сырец всегда доступен в карточке, аудио хранится — истина восстановима |
| Опция | GigaAM-Emo (эмоции) — не подключать в R1, записать как идею для окраски срочности в R2 |

Бюджет: клип 30 с → ASR ≤ 3 с на 8 vCPU. Замерить на своём железе в первый день — это допущение, не факт.

### 2.2. LLM-стадия (DeepSeek)

Один вызов, не два (вход крошечный, стримить нечего):

- `model: deepseek-v4-flash`, non-thinking, `temperature: 0.1`, `response_format: {"type":"json_object"}`, `max_tokens: 2048`;
- слово «json» и пример структуры — обязательны в промпте (требование провайдера);
- документированная особенность: изредка пустой `content` → до 2 ретраев, затем деградация §6;
- стоимость: вход ~1.5К токенов, выход ~0.5К → **~$0.0005 на запись**; расход даже при 20 записях в день — копейки в месяц;
- Опция «качество» (`deepseek-v4-pro`) — флаг конфига, в R1 не дефолт.

## 3. Модель данных (SQLite на устройстве)

```sql
notes(
  id TEXT PK,             -- ulid
  created_at INTEGER,     -- unixtime записи (момент нажатия!)
  audio_path TEXT,        -- локальный файл, хранится всегда
  transcript TEXT NULL,   -- сырец ASR
  status TEXT,            -- recorded | queued | sent | parsed | failed_asr | failed_llm
  duration_ms INTEGER
);

items(
  id TEXT PK, note_id FK,
  type TEXT,              -- buy | do | tell | date | thought | fact
  text TEXT,              -- нормализованная формулировка (≤ 120 зн.)
  who TEXT NULL,          -- кому сказать / с кем связано
  due_kind TEXT,          -- none | window | exact
  window TEXT NULL,       -- morning | day | evening | tomorrow_morning | weekend
  due_at INTEGER NULL,    -- unixtime для exact
  state TEXT,             -- planned | returned | done | snoozed | dismissed | expired
  confidence TEXT,        -- high | medium | low
  raw_span TEXT NULL      -- кусок транскрипта-источника (для доверия/отладки)
);

returns(
  id TEXT PK, item_id FK,
  scheduled_at INTEGER, fired_at INTEGER NULL,
  action TEXT NULL,       -- done | later | miss | ignored
  attempt INTEGER         -- 1 | 2 (третьего нет — дальше R2-разбор)
);
```

Инварианты (код, не модель): `type` из белого списка; `due_at` только в будущем;
`text` обрезается по слову; `who` — только если явно прозвучал; HTML невозможен
(рендер через текст). Айтем с непрошедшей валидацией не выбрасывается, а падает в
`type=thought, due_kind=none` — **запись пользователя не теряется никогда**.

## 4. Промпт разбора (ядро продукта)

Системный промпт (рус., сокращённая суть — финальная редакция в репо, версионируется):

> Ты — тихий помощник в приложении «Принял». Пользователь наговорил на бегу комок
> мыслей и дел. Разбери его на отдельные пункты и верни ТОЛЬКО json по схеме.
> Правила: (1) не выдумывай пункты, которых нет в тексте; каждый пункт снабжай
> `raw_span` — фрагментом исходника; (2) не выдумывай время: если срок не прозвучал —
> подбери разумное окно (`morning|day|evening|tomorrow_morning|weekend`) по здравому
> смыслу («позвонить в поликлинику» → рабочие часы; «не забыть утром» →
> tomorrow_morning), а если и окно не очевидно — `none`; (3) `exact` только если
> время названо явно; (4) формулируй пункт коротко и в исходных словах пользователя,
> без канцелярита; (5) «сказать/спросить/написать кому-то» → type=tell + `who`;
> (6) факт о мире без действия («паспорта в синей коробке») → type=fact;
> (7) сомневаешься в разборе пункта — ставь `confidence: low`, не маскируй.

Схема ответа:

```jsonc
{ "items": [ { "type": "do", "text": "позвонить в поликлинику насчёт Сони",
               "who": null, "due_kind": "window", "window": "day",
               "due_at": null, "confidence": "high",
               "raw_span": "соню к лору записать" } ] }
```

Планировщик (код, не модель) превращает `window` в timestamp по конфигу окон
пользователя (дефолт: morning 8:00, day 12:30, evening 19:30, weekend сб 11:00;
правило «окно уже прошло сегодня → ближайшее такое же завтра», правило «evening-айтем,
записанный в 21:50 → сегодня 22:00, если не позже 22:30»). Модель предлагает
семантику, время назначает код — принцип недоверия из «Параллелей» сохраняется.

### 4.1. Интерфейсные строки — правила и словарь R1

Все строки UI живут в одном словаре (`strings.xml`), правки — только через него. Правила:

1. **Буквальность важнее образности.** Строка описывает, что произошло или что будет, простыми словами. Метафоры («сервер спит»), остроумие и игривость — запрещены, особенно в ошибках: уставший человек в шторке должен понять смысл за секунду, не разгадывая тон.
2. **«Комок» — внутренний термин** (команды и промпта), в UI не появляется никогда. Пользовательский эквивалент, если нужен: «всё, что в голове» / «вперемешку».
3. Разговорность допустима («напомню», «посмотри»), фамильярность — нет («глянь», «чекни»).
4. Кнопки действий — 1–2 слова с очевидным исходом: **сделано / позже / не надо**.
5. Чек-лист ревью каждой строки: поймёт ли смысл человек, который видит её впервые, на бегу, за одну секунду. Нет — переписать проще.

Словарь ключевых строк R1 (канон, менять только здесь):

| Контекст | Строка |
|---|---|
| Квитанция | «Принял.» |
| План айтема | «верну в 19:30» / «напомню завтра утром» / «просто сохраню» |
| Низкая уверенность | «не уверен, что понял — проверь» |
| Причина возврата | «вечер — ты просил вернуть» / «утро — сам назначил на утро» |
| Действия возврата | «сделано» / «позже» / «не надо» |
| Подтверждение «позже» | «ок, верну завтра утром» |
| Пачка после оффлайна | «разобрал 3 записи за утро» |
| Нет связи с бэкендом | «нет связи с сервером — записи сохраняются, разберу позже» |
| Ошибка разбора (fallback) | «не смог разобрать — посмотри сам, верну вечером» |
| Кончился баланс | «на ключе DeepSeek кончились средства» |

## 5. Требования

### F-1 · Захват capture-first
Иконка открывает приложение **сразу в запись**: разрешение микрофона получено заранее,
`MediaRecorder` стартует в `onCreate` до отрисовки. Виджет 1×1 и плитка QS ведут туда же.
Экран: пульс, таймер, тап = стоп, свайп вниз = отмена. Авто-стоп: 2 с тишины
(порог амплитуды) после ≥ 3 с речи, потолок 90 с.
*Приёмка:* от тапа по виджету до фактического начала записи ≤ 700 мс на своём
телефоне (замер логами); запись работает при заблокированном интернете; повторный
тап виджета во время записи останавливает, а не плодит вторую.

### F-2 · Квитанция «Принял.»
Мгновенно по стопу: слово «Принял.» + фирменное вибро (паттерн из ТЗ айдентики,
пока — двойной короткий), экран закрывается сам через 0.6 с. Квитанция **не ждёт**
ни сети, ни ASR — она подтверждает захват, не разбор.
*Приёмка:* квитанция идентична при живой сети и в самолётном режиме.

### F-3 · Оффлайн-очередь и отправка
Каждая запись немедленно в SQLite (`recorded`) → WorkManager-задача отправки с
ретраями и backoff, состояние `queued/sent`. Очередь переживает перезагрузку.
*Приёмка:* 5 записей в самолётном режиме → включение сети → все 5 разобраны без
участия пользователя; ни одна запись не теряется при убийстве процесса в момент стопа.

### F-4 · Конвейер бэкенда
`POST /ingest` (audio, note_id, client_ts, timezone) → ffmpeg → VAD → GigaAM →
DeepSeek → `{transcript, items[]}`. Токен-авторизация. Таймауты: ASR 20 с, LLM 15 с.
Логи запросов — off по умолчанию (флаг для отладки).
*Приёмка:* медиана «стоп → items на устройстве» ≤ 6 с на клипе 20 с (замер по
логам за первую неделю); пустой `content` DeepSeek воспроизводится тестом и уходит
в ретрай; бэкенд поднимается одним `docker compose up`.

### F-5 · «Доказательство понимания»
Как только items пришли — нотификация-карточка (и экран в приложении): список
пунктов с иконкой типа, планом («верну в 19:30», «напомню завтра утром», «просто
сохраню») и `confidence: low` — приглушённо, с пометкой «не уверен». Тап по пункту —
правка (тип/окно/текст), «не надо» — один тап (айтем → dismissed, событие в аналитику).
*Приёмка:* сценарий «капли, Соню к лору, мужу про субботу» из ТЗ разбирается на
3 пункта с разными планами; сценарий «counter клиенту по цене» даёт do + window=day
+ пометку низкой уверенности при отсутствии деталей; правка окна пересчитывает
возврат немедленно.

### F-6 · Возвраты
Локальные уведомления по `returns.scheduled_at` (AlarmManager, exact — запросить
разрешение Android 12+; появление в течение минуты от плана). Нотификация: текст
айтема + причина («вечер — ты просил вернуть») + 3 действия: **сделано / позже /
не надо**. «Позже» — без выбора времени: код сам ставит следующее окно и пишет это в
нотификацию подтверждением. Проигнорированная (свайп/без действия) — один тихий
второй заход в следующее окно (`attempt 2`), затем `expired` (ждёт R2-разбора, не
пилит).
*Приёмка:* возврат срабатывает при убитом приложении и после перезагрузки телефона;
на MIUI-подобной прошивке с дефолтными оптимизациями батареи — проверить и
задокументировать фактическое поведение (это данные для гипотезы, не только QA);
«позже» вечером в 21:55 не назначает 23:40, а уходит на завтра.

### F-7 · Лента и карточка
Лента: хронология записей со статусами айтемов; фильтра и папок нет. Карточка:
аудио-плеер, транскрипт-сырец, айтемы с `raw_span`-подсветкой, история возвратов.
Действия: похоронить айтем вручную, перезапустить разбор (после ошибки).
*Приёмка:* от записи в ленте до прослушивания аудио — 2 тапа; `failed_*` записи
видны и перезапускаемы.

### F-8 · Настройки (минимум)
Адрес бэкенда + токен; окна дня (4 слайдера времени); тумблер «отправлять текст в
DeepSeek» (off → деградация §6, честная надпись что перестаёт работать); экспорт
всей базы в JSON одним файлом (страховка dogfood-данных).
*Приёмка:* экспорт-файл реимпортируется на чистой установке.

### F-9 · Аналитика под kill-критерии
`analytics.jsonl` локально: `capture_start/stop/cancel` (источник: icon|widget|tile),
`receipt_shown`, `parse_ok/fail` (n items, длительности ASR/LLM, ретраи),
`items_per_note`, `return_fired/action`, `edit_item`, `miss_item`.
Раз в неделю приложение само показывает сводку: дней с записью / записей в день /
медиана айтемов на запись (**< 1.5 = диктуются команды, а не комки — тревога по
kill-критерию 2**) / доля возвратов с действием / доля «не надо».
*Приёмка:* сводка считается корректно на синтетической неделе данных.

## 6. Деградации

| Ситуация | Поведение |
|---|---|
| Нет сети | Полный захват + квитанция; очередь; айтемы придут позже — нотификация «разобрал 3 утренних записи» одной пачкой |
| Бэкенд недоступен | То же, что нет сети + бейдж в ленте «нет связи с сервером»; ретраи по backoff до часа, дальше — по открытию приложения |
| ASR упал / пустой транскрипт | `failed_asr`, аудио цело, кнопка «повторить»; нотификация без драмы |
| DeepSeek: пустой content / 5xx / таймаут | 2 ретрая → **fallback-план**: note целиком становится одним айтемом `type=thought`, транскрипт как текст, возврат в ближайший вечер («не смог разобрать — посмотри сам»). Петля деградирует, но не рвётся |
| DeepSeek 402 (баланс) | Отдельный текст «кончились средства на ключе» + fallback-план |
| Тумблер DeepSeek off | Всегда fallback-план: продукт превращается в «голосовые с вечерним возвратом» — честная минимальная петля без LLM |
| Запись < 1.5 с | Не отправляется, тихо удаляется (случайные нажатия) |

## 7. Безопасность и приватность (dogfood-уровень, но не ниже)

- Аудио: телефон + свой сервер (transit TLS, self-hosted → свой контур), третьим лицам не уходит.
- Текст: уходит в DeepSeek (внешний сервис) — осознанное решение владельца, тумблер F-8.
- Ключ DeepSeek — только на бэкенде, в env; токен бэкенда — в EncryptedSharedPreferences.
- Бэкенд наружу — только через reverse-proxy с TLS (caddy в том же compose) либо VPN/tailscale до сервера (предпочтительно: вообще без публичного порта).

## 8. Метрики версии (2 недели личного прогона)

| Метрика | Считаем | Порог решения |
|---|---|---|
| Живость жеста | дней с ≥ 1 записью / 14 | < 60% → kill-критерий 1 под вопросом, < 30% → закрытие |
| Комок vs команда | медиана items/note | ≥ 2 — комки идут; < 1.5 — Siri-клон, kill-критерий 2 |
| Петля замыкается | доля айтемов с действием на возврате (done+позже) | ≥ 50% |
| Мусор разбора | доля «не надо» + ручных правок | ≤ 20%; выше — промпт/валидацию править до любых новых фич |
| Латентность понимания | медиана стоп→items | ≤ 6 с |
| Надёжность возвратов | fired в пределах 2 мин от плана | ≥ 95% (меньше — виновата прошивка, чинить до выводов о продукте) |
| Стоимость | биллинг DeepSeek | справочно, ожидание < $1/мес |

Правило честности: первые 3 дня — обкатка, в метрики не идут.

## 10. Срезы

**R1 (эта версия), ~3 недели вечеров:**
нед. 1 — бэкенд (compose: fastapi+ffmpeg+GigaAM+silero-vad; /ingest end-to-end с curl) + замер латентности; нед. 2 — приложение: F-1…F-5 (петля до карточки понимания); нед. 3 — F-6…F-9 + прогон деградаций. Далее — 14 дней жизни и вердикт по §8.

**R2 (только после вердикта «петля жива»):** доукомплектация (пакетный вечерний заход), агрегация «купить»-айтемов в список, недельный разбор, роль ассистента (кнопка питания), гео-окно «дома», исследование on-device ASR.

**R3:** память фактов (type=fact уже копится с R1 — задел сделан), пакет к событию из собственных date-айтемов, затеи.

## 11. Открытые вопросы

1. **VAD-автостоп vs фикс-потолок:** порог тишины на шумной улице может резать речь — в R1 сделать порог настраиваемым и посмотреть на свои `cancel`-события.
2. **Окна планировщика:** дефолты §4 — гипотеза; после недели скорректировать по фактическим `later`-переносам (куда я сам переношу — там и окно).
3. **`type=fact` в возвратах:** факты не возвращать вовсе (копятся молча) или показать в вечерней сводке дня? В R1 — не возвращать, наблюдение отложить.
4. **Уведомление-пачка после оффлайна:** одна сводная или по-штучно? В R1 — сводная; по-штучно раздражает после утра без сети.
