# GigaAM на своём сервере

Как включить настоящее распознавание вместо стаба и как замерить, укладываемся ли мы
в бюджет PRD §2.1 (клип 30 с → ASR ≤ 3 с на 8 vCPU). **Это допущение, а не факт** —
замерить на своём железе в первый день.

## Два пути инференса

`app/asr/gigaam.py` выбирает путь сам (`ASR_GIGAAM_MODE=auto|package|onnx`):

| Путь | Что нужно | Когда брать |
|---|---|---|
| `package` | пакет `gigaam` + torch (CPU) | по умолчанию: сам считает признаки и декодирует RNNT, нечему разъезжаться |
| `onnx` | экспортированный граф + onnxruntime | когда важна память и скорость старта |

Путь `package` — рекомендуемый для дня 1. К `onnx` переходить, когда замер покажет,
что torch не укладывается в бюджет.

## Путь `package`

```bash
cd backend
docker compose --profile asr build
```

Веса тянутся при первом старте в `ASR_MODEL_PATH` (том `./models`). Модель по
умолчанию — `v2_rnnt` (`ASR_GIGAAM_MODEL`).

```bash
PRINYAL_API_TOKEN=... DEEPSEEK_API_KEY=... docker compose --profile asr up -d
curl -s localhost:8080/health | jq
```

В ответе `asr: "gigaam"` и `asr_mode: "package"` — значит движок поднялся.

## Путь `onnx`

Экспорт делается один раз, на машине с torch:

```python
import gigaam
model = gigaam.load_model("v2_rnnt", device="cpu")
model.to_onnx(dir_path="models/gigaam")
```

В каталоге должны оказаться три графа (`*encoder*.onnx`, `*decoder*.onnx`,
`*joint*.onnx`) и `tokens.txt` со словарём — по одному токену в строке.

**Что проверить перед тем, как верить результату.** Адаптер сверяет имена входов
энкодера (`audio_signal`, `length`) и падает с внятной ошибкой, если экспорт другой.
Но три вещи он проверить не может, и они молча портят распознавание, не роняя сервис:

1. **Мел-фильтры.** `ASR_N_MELS` по умолчанию 64. Если экспорт обучен на другом числе
   фильтров или другой нормализации, текст будет похож на речь, но неверный.
2. **Раскладка выхода энкодера.** Адаптер ожидает `(B, D, T)` и транспонирует по
   длине; при другой раскладке декод развалится в кашу.
3. **Позиция blank.** Считается последним индексом словаря. Если в экспорте он
   первый, каждый кадр будет давать пустой символ и транскрипт окажется пустым.

Поэтому первый прогон — на клипе, где вы знаете правильный текст. Пустой или
бессмысленный транскрипт при живом сервисе означает одну из этих трёх причин, а не
качество модели.

## Замер латентности (день 1)

```bash
cd backend
.venv/bin/python scripts/measure_latency.py --url http://localhost:8080 \
  --token "$PRINYAL_API_TOKEN" --seconds 30 --runs 5
```

Скрипт делает клип нужной длины, гоняет `/ingest` и печатает медиану `asr_ms`,
`llm_ms` и полного круга. Сверять с §8: медиана «стоп → items» ≤ 6 с.

Если не укладывается — план Б из §9: квантованный ONNX, модель поменьше или аренда
CPU. Сначала цифры, потом решение.

## VAD

`VAD_BACKEND=silero` включает Silero VAD (нужен torch — он уже в слое `asr`).
`energy` — амплитудный фолбэк, работает без тяжёлых зависимостей и достаточен для
клипов до 90 с. Клипы короче `VAD_MIN_SPLIT_S` (20 с) не режутся вовсе.

## Известная зона ошибок

Числа и имена — слабое место ASR (PRD §9). Продукт с этим живёт так: пункты
показывают текст, нормализованный моделью, но транскрипт-сырец всегда доступен в
карточке, а аудио хранится — истина восстановима.

Копите `failed`-примеры неделю; дешёвый костыль до R2 — словарь подсказок в промпт
DeepSeek («в моей речи часто: …»).
