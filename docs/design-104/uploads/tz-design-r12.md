# ТЗ дизайнеру · R1.2

Четыре задачи по итогам двух дней жизни владельца с приложением. Основа прежняя:
токены `assets/design-tokens.json`, словарь строк по правилам PRD §4.1, запреты
айдентики (без микрофонов, волн-эквалайзеров, галочек-задач). Скрины текущего
состояния — `docs/ui-review/`.

---

## 1. Состояния клавиши записи: idle / запись / стоп кнопкой

Сейчас экран записи всегда «пишет»: иконка открывает приложение сразу в запись
(capture-first — решено, не трогаем), стоп — тап по любому месту экрана. Владелец:
тап по пустоте не читается как действие — нужна **явная кнопка «завершить
запись», обыгранная большой красной клавишей в центре**. Плюс появилось новое
состояние: после возврата из ленты запись не идёт — клавиша впервые оказывается
в «не пишу».

Спроектировать три состояния клавиши (геометрия из токенов `key`: корпус 112,
колпачок 84, нажатый 78, точка 26):

1. **Запись идёт** — клавиша = кнопка «стоп». Как выглядит нажатие (глубина, ход
   колпачка), что происходит с пульсом в момент нажатия. Решить: тап по экрану
   вне клавиши — тоже стоп (как сейчас) или только клавиша.
2. **Idle** — клавиша = кнопка «начать». Чем idle отличается от записи визуально,
   кроме отсутствия пульса: человек с одного взгляда понимает, пишет телефон
   или нет.
3. **Переход idle → запись** по нажатию: моушн в терминах токенов `motion`.

Приёмка: человек вне команды по скриншоту отвечает, идёт ли запись, и говорит,
куда нажать, чтобы остановить/начать.

## 2. Таймер и живая индикация записи

Боль владельца: «таймер маленький и непонятный», «не видно, пишется ли речь».
Сейчас: моно-таймер 30sp над клавишей + пульс-кольцо вокруг неё. Амплитуда голоса
уже прокинута в UI (значение 0..1, тик каждые 100 мс) — индикацию можно строить
прямо на ней, разработки это не потребует.

Задача: спроектировать индикацию «я тебя слышу» без клише волны (запрет
айдентики §4). Направления на выбор, не ограничиваться ими: дыхание самой клавиши
от громкости; кольцо-пульс с амплитудой; наливающаяся точка. Таймер: размер,
место, поведение — возможно, он растворяется во время речи и проявляется в
тишине. Отдельно показать **тишину**: человек замолчал, через 2 секунды будет
авто-стоп — сейчас авто-стоп ощущается внезапным.

Моушн-спека в терминах токенов; интерполяцию между 100-мс тиками амплитуды
задать явно.

## 3. Ребрендинг: «Запомин.ai», квитанция «Запомнил.»

Решение владельца 07.08.2026: имя приложения — **Запомин.ai**, квитанция —
**«Запомнил.»** (вместо «Принял.»).

Что отработать честно, а не проигнорировать: айдентика строилась на правиле «имя
продукта = его реплика» (ТЗ айдентики §2). Пара «Запомин.ai / Запомнил.» правило
сохраняет — но леттеринг квитанции, вибро-паттерн и иконка проектировались под
слово короче. Проверить: как «Запомнил.» ложится в кегль display 38 на узких
экранах; не ломается ли ритм точки. Иконку владелец менять не просил — по
умолчанию не трогать.

Сдать: выверенную квитанцию «Запомнил.» (кегль/трекинг — правкой токенов, если
нужно), правило написания имени (регистр, точка, сторы, текст), ревизию строк
словаря, где встречается «принял».

## 4. Правка транскрипта в карточке записи

Модель часто ослышивается («соник лору»), пункты правятся, а исходный транскрипт
— нет. Спроектировать режим правки блока «Что услышал» в карточке записи:

- вход в правку (тап по тексту? отдельное действие?);
- поведение подсветки фрагментов-источников (raw_span) при редактировании —
  гаснет или живёт;
- выход: «Разобрать заново» / «Отмена».

Тон — правка текста, не форма: без тулбаров и форматирования. После переразбора
пункты пересобираются, и ручные правки пунктов пропадают — предупредить одной
честной строкой в тоне §4.1 (без «Вы уверены?»).
