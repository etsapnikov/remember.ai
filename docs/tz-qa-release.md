# Запомин.ai · ТЗ на QA продукта при релизах

| | |
|---|---|
| **Версия** | 1.0 |
| **Дата** | 17 августа 2026 |
| **База** | Состояние 1.0, объёмы 1.0.1/1.0.2, Р-15.16 (автотесты) |
| **Коды** | **QA-1 … QA-10** |

**Место документа.** Автотесты (Р-15.16, ярусы 1–2) ловят регрессии кода и дрейф
модели — они гейт мержа и гейт промпта. Этот документ — **гейт релиза**: что
проверяется руками и на живом устройстве перед тем, как версия становится
рабочей. Пока продукт dogfood, QA-роль исполняет владелец; документ написан так,
чтобы при появлении тестировщика передаваться без пересказа.

**Специфика продукта, из которой растёт весь документ:** (1) в петле два
недетерминированных звена — ASR и LLM; (2) продукт живёт в фоне на китайских
прошивках, где фон убивают; (3) база — единственная копия данных владельца,
миграции необратимы; (4) главный экран продукта — шторка уведомлений.

---

## QA-1 · Типы релизов и глубина прогона

| Тип | Что менялось | Прогон |
|---|---|---|
| **patch** (1.0.2.x) | багфикс без схемы, промпта и новых экранов | QA-3 (смоук петли) + точечный регресс зоны фикса |
| **minor** (1.0.x) | фичи, схема, промпты, экраны | Полный: QA-3…QA-9 + eval-гейт яруса 2 |
| **обновление зависимостей** (GigaAM/onnx/DeepSeek-модель) | рантайм | QA-3 + ASR-регресс (5 эталонных wav посимвольно) + eval-гейт |

Правило: правка системного промпта = minor всегда, даже если «одно слово».

## QA-2 · Стенд и матрица условий

- **Устройства:** основное (Honor Magic6 Pro, живая база владельца — см. QA-4
  про безопасность) + одно контрольное с чистой установкой (желательно другой
  вендор/дешёвый сегмент, эмулятор допустим для функционала, но не для
  уведомлений и батареи).
- **Матрица условий** (каждый minor-прогон, применяется к зонам QA-5…QA-7):
  сеть норм / оффлайн / медленная (троттлинг 10 с); батарея норм / режим
  энергосбережения; светлая / тёмная тема; шрифт системный / крупный.

## QA-3 · Смоук петли (обязателен всегда, ~30 мин)

Ручной сквозной прогон, 14 шагов, каждый — «прошёл/нет»:
1. Холодный старт → экран записи ≤ 1 с, кольцо живое.
2. Запись 20 с → «Запомнил.» + вибро мгновенно.
3. Разбор: анимация живая, пункты доехали, чип раздела встал.
4. Разбор в оффлайне: квитанция есть, очередь видна, после сети — доезд пачкой.
5. Пункт: тап = раскрытие read-only; правка за жестом; правка окна ≤ 2 жестов.
6. Явная дата голосом («вернуть 10 сентября») → exact, виден в пункте.
7. Возврат пришёл в окно ±2 мин; «сделано/позже/не надо» работают из шторки.
8. «Позже» вечером → перенос на завтра, не на ночь.
9. Дописывание: экран открылся с плашкой, сегмент добавился, done-пункты не
   воскресли.
10. Заметка-идея: «покрутить» задаёт вопрос, ответ стал сегментом.
11. Разделы: заметка видна в своём, «Без раздела» ведёт себя тихо.
12. Неделя: факты без похвалы, счётчики на месте в «Для разработчика».
13. Контекст-пак по разделу: 4 секции, даты, «копировать» отдаёт md.
14. Убийство процесса после записи → ничего не потеряно.

## QA-4 · Данные и миграции (самая дорогая зона)

- Перед любым прогоном на основном устройстве — **экспорт базы** (F-8) в
  датированный файл; прогон minor начинается с проверки экспорт→импорт на
  контрольном устройстве.
- **Миграционный тест:** копия живой базы прошлой версии → установка новой →
  все заметки/пункты/состояния/топики/линки на месте (сверка счётчиков до/
  после), приложение не падает на старых записях без новых полей.
- **Даунгрейд не поддерживаем** — но проверяем, что новая версия не портит базу
  до неоткрываемости старой резервной копией (восстановление из экспорта
  работает).
- Часовые пояса: смена TZ на устройстве после установки возвратов → возвраты
  срабатывают по локальному времени без дублей (известная зона багов
  AlarmManager).

## QA-5 · Возвраты и фон (прошивочная зона)

На каждом minor, на реальном устройстве, не эмуляторе:
- возврат при убитом приложении; после перезагрузки; в режиме энергосбережения;
- поведение при запрете точных будильников (Android 12+): продукт честно
  просит разрешение, без разрешения деградирует предсказуемо (окно ±15 мин),
  а не молчит;
- 3 возврата в одну минуту → не слипаются в один, действия каждого работают;
- полночь во время активной записи/разбора ничего не рвёт.
Результаты фиксируются в отчёте даже когда «виновата прошивка» — это данные
продукта, не только QA.

## QA-6 · Недетерминированные звенья (ручная выборка поверх eval)

Eval яруса 2 даёт проценты; руками проверяется то, что метрики не видят:
- **5 живых записей** голосом владельца (не фикстуры!): естественная речь,
  фоновый шум, термины из словаря замен → субъективная оценка разбора по
  чек-листу: пункты не потеряны / не выдуманы / формулировки не канцелярит /
  раздел осмыслен;
- **тон**: все новые строки версии прочитаны вслух против правил 4.1 PRD
  (буквальность, без похвалы, без фамильярности); стоп-слова ищутся grep'ом
  по strings.xml;
- **1 контекст-пак и 1 сессия интервьюера** — ручная сверка «нет утверждений
  вне корпуса / нет генерик-вопросов».

## QA-7 · Краевые записи (набор живых кейсов)

Гоняются голосом при каждом minor: запись 3 с («молоко») / запись 90 с с
автостопом / запись с паузами по 4 с (VAD не режет) / диктовка с числами и
датами / имя из словаря замен / две несвязанные темы (сплит) / тема с бытовым
хвостом (не сплит) / запись на шумной улице / повторный тап виджета во время
записи / запись во время входящего звонка.

## QA-8 · Приватность и контур (каждый minor)

- Ключ DeepSeek не встречается в логах и экспорте (grep по дампу);
- наружу уходит только текст: перехват трафика (или лог запросов) — аудио в
  запросах отсутствует, эндпоинты только DeepSeek;
- «Для разработчика» не светит содержимое заметок в системный логкат.

## QA-9 · Производительность (бюджеты из PRD/объёмов)

Замеры логами на основном устройстве: старт ≤ 1 с; тап виджета → запись
≤ 700 мс; стоп → пункты ≤ 6 с медиана (10 записей); лента 1000 заметок — скролл
без просадок; «Разделы» ≤ 300 мс; батарея за сутки фона — без появления в
топе потребителей.

## QA-10 · Процесс, вердикт и отчёт

- **Блокер** (релиз не выходит): потеря/порча данных; петля рвётся на любом
  шаге QA-3; возвраты молчат на основном устройстве; провал eval-гейта или
  стоп-листов; ключ/аудио в трафике.
- **Некритично** (выходит с заведённой задачей): косметика, единичные огрехи
  разбора в QA-6, прошивочные особенности с понятным обходом.
- **Отчёт релиза** (шаблон, 1 страница): версия/дата; тип прогона; QA-3
  таблицей; найденное по зонам с вердиктами; ссылка на eval-report; решение
  выпускать/нет и кто принял. Отчёты копятся в репо рядом с eval-report'ами —
  это история здоровья продукта.
- Найденный руками баг обязан получить фикстуру/шаг: в ярус 1 (если код), в
  eval (если модель), в QA-3/QA-7 (если сценарий) — чек-лист растёт только из
  реальных падений, а не из фантазий.

## Порядок внедрения

Первый полный прогон — на релизе 1.0.2 (он же обкатка документа: шаги, которые
оказались лишними/непонятными, правятся сразу). До него — завести экспорт-
резервирование (QA-4) прямо сейчас: это единственный пункт, который опасно
откладывать даже на dogfood.
