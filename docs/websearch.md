# Веб-поиск у DeepSeek — проверено на живом API

Р-13.5. Проверялось 14 августа 2026 боевым ключом, не по документации:
источники в сети противоречили друг другу, обзоры цен утверждали, что
хостед-инструментов у DeepSeek нет. Они ошибаются.

## Ответ: есть

Серверный поиск работает. Модель сама решает, что нужно искать, сама
формулирует запросы и сама читает выдачу — на стороне DeepSeek, без нашего
поискового API и без второго ключа.

**Но только на Anthropic-совместимом эндпоинте.**

```
POST https://api.deepseek.com/anthropic/v1/messages
x-api-key: <ключ>
anthropic-version: 2023-06-01

"tools": [{"type": "web_search_20260209", "name": "web_search", "max_uses": 3}]
```

Тот эндпоинт, которым приложение пользуется сейчас
(`/chat/completions`, OpenAI-совместимый), поиск **не поддерживает** — отвечает
`unknown variant 'web_search_20260209', expected 'function'`. Это значит второй
клиент в коде: разбор комка остаётся где был, факт-чекинг ходит по другому пути.

## Что приходит в ответе

Блоки `server_tool_use` (какие запросы модель придумала), затем
`web_search_tool_result` — по 10 источников на запрос, у каждого заголовок и
адрес, — затем обычный текст ответа.

Форма ровно та, что нужна артефакту 3b: вердикт словом и список оснований,
которые можно показать названием без ссылок-простыней.

## Цена и время

Замер на медицинском вопросе, `deepseek-v4-flash`, 2 поисковых запроса:

| | |
|---|---|
| время | 9,5 с |
| входных токенов | 8 346 (выдача вклеивается в контекст) |
| выходных | 756 |
| стоимость | ≈ **0,0014 $** за проверку |
| отдельная плата за поиск | в `usage` считается (`web_search_requests: 2`), в прайсе не заявлена |

Тысяча проверок — меньше двух долларов. Цена решением не является.

Девять секунд — тоже не проблема: макет 3b и так описывает факт-чекинг как
единственный тип, который не готов сразу («проверяю…» в ленте, вердикт приезжает
позже). Наоборот, замер подтверждает, что решение дизайнера было правильным.

## Что придётся сделать сверх «включить»

**1. Фильтровать источники.** Главная находка и главный риск. На вопрос о
детских каплях модель вернула вперемешку клинический формуляр NHS Scotland и
китайские аптечные витрины (`tzzxy.cn`, `tqyiyao.com`). Макет обещает
«Инструкция к ксилометазолину · РЛС · 2024» — такой источник надо выбирать, а не
брать первый попавшийся. Без ранжирования артефакт будет ссылаться на мусор, и
это опаснее отсутствия ответа: ссылка придаёт вес.

Значит нужен явный отбор: язык запроса, приоритет инструкций и клинических
рекомендаций, отсев торговых площадок.

**2. Собрать структуру отдельно.** Ответ приходит связным текстом с markdown-
таблицами, а карточке нужен json: вердикт из четырёх градаций, объяснение,
список источников. `response_format: json_object` на Anthropic-эндпоинте нет.
Значит либо второй дешёвый вызов, который сворачивает найденное в схему, либо
структурированный вывод через обычный tool call. Второй вызов проще и
предсказуемее.

**3. Поднять потолок токенов.** На 600 ответ обрывается (`stop_reason:
max_tokens`) — выдача съедает контекст. Нужно считать бюджет от числа
источников, а не константой.

## Что это меняет в плане

Факт-чекинг из «нельзя выпускать» становится «можно, если отобрать источники».
Задачи дизайнеру Диз-13.3 (состояние «источников нет») и Диз-13.4 (тип «поиск»)
остаются в силе: состояние без ответа всё равно нужно — сеть отваливается, а
поиск иногда не находит ничего.

Решение по объёму — за владельцем.
