# Принял · prinim.ai

MVP «Одна петля» (R1, dogfood). Реализация [PRD](docs/prd-prinyal-mvp.md) — нажал,
наговорил, получил «Принял.», через секунды увидел разобранный план, в правильные
окна дня получил возвраты в шторку.

Версия существует, чтобы честно ответить на один вопрос: **удерживает ли голая
петля**. Всё, чего нет в PRD §1 «В версии», сюда не добавляется — даже «быстренько».

## Что где

```
backend/     FastAPI: /ingest → ffmpeg → VAD → GigaAM → DeepSeek → айтемы
android/     Kotlin/Compose: захват, очередь, планировщик возвратов, лента
assets/      design-tokens.json и иконки — источник истины дизайн-системы
docs/        PRD, ТЗ UI, ТЗ айдентики, заметки по GigaAM
```

Устройство — источник истины. Записи, пункты и расписание возвратов живут в SQLite на
телефоне, уведомления локальные. Бэкенд может лежать: петля деградирует, но данные не
теряются и продукт не молчит.

## Бэкенд

```bash
cd backend
cp .env.example .env      # PRINYAL_API_TOKEN, DEEPSEEK_API_KEY
docker compose up -d      # лёгкий контур со стаб-ASR
curl -s localhost:8080/health
```

Настоящее распознавание — профиль `asr` и [docs/gigaam.md](docs/gigaam.md):

```bash
docker compose --profile asr up -d
```

Наружу бэкенд лучше не выставлять вовсе: предпочтительный доступ — tailscale до
сервера. Если нужен публичный адрес — профиль `tls` поднимает caddy с сертификатом.

Разработка и тесты:

```bash
cd backend
python3.12 -m venv .venv && .venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

## Приложение

```bash
cd android
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
```

Нужен JDK 17 и Android SDK 35. Путь к SDK — в `local.properties`.

В настройках приложения задать адрес бэкенда и токен (тот же
`PRINYAL_API_TOKEN`), затем поставить виджет 1×1 на домашний экран — он и есть
основная кнопка.

## Дизайн-система

`assets/design-tokens.json` — единственный источник цвета, типографики, отступов,
моушна и вибро. В коде он развёрнут в `ui/theme/` (Compose) и `res/values/colors.xml`
(системные поверхности). Правка цвета начинается с токенов, а не с экрана.

Семантика цвета — правило, а не рекомендация:

- `record` — только клавиша записи, её пульс и таймер записи;
- `accentSelf` — всё, что продукт сделал сам: планы, возвраты, квитанция, причина;
- `done` — только состояние done у пункта;
- красный вне жеста записи, зелёный вне done и синий где угодно — запрещены.

Все интерфейсные строки живут в `res/values/strings.xml` и только там. Правила
формулировок — PRD §4.1: буквальность важнее образности, «комок» в UI не появляется
никогда, кнопки — 1–2 слова с очевидным исходом.

## Что дальше

Две недели личного прогона, потом вердикт по числам §8. Сводка считается сама
(экран «Неделя»), пороги записаны заранее:

| Метрика | Порог |
|---|---|
| Дней с записью | ≥ 60% из 14; < 30% — закрытие |
| Медиана пунктов на запись | ≥ 2; < 1,5 — это Siri-клон |
| Возвратов с ответом | ≥ 50% |
| «Не надо» + правки | ≤ 20% |
| Медиана стоп → пункты | ≤ 6 с |
| Возвраты в пределах 2 мин от плана | ≥ 95% |

Первые три дня — обкатка, в метрики не идут.
